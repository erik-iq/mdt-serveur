Valider un déploiement Windows et HP

Le suivi Image appliquée confirme seulement la préparation du disque. Un résultat WinGet confirme la présence des applications, pas la mise à jour des pilotes par HPIA. Un code HPIA zéro avec seulement Analyze Action List ne prouve aucune installation de SoftPaq. La validation combine les rapports, une analyse récente après redémarrage et les essais du technicien.

Livraison IQ-5.5 - suivi serveur et maintenance réduite

Les pages HPIA et pilotes et Images et correctifs sont testées dans un navigateur de bureau et a 390 pixels : recherche, métadonnées CVA, stockage, erreurs, nouveaux correctifs et téléchargement JSON. Les textes issus des postes et des CVA sont echappes. Les endpoints demandent l’autorisation administrateur et n’exposent pas les clés des agents ou les fichiers de configuration. La recherche du catalogue est bornee à un budget réseau de 90 secondes sur le site et reste distincte d’une installation.

Les tests de maintenance simulent un WIM multi-edition puis verifient les exports fast de Core/Professional, le changement d’index, la conservation de l’original, le refus des erreurs DISM et des paquets modifiés. Un candidat intact avec les mêmes KB est réutilisé ; une source déjà préparée ne relance pas DISM ; une nouvelle sélection, une candidate modifiée ou un rapport annulé provoquent une nouvelle préparation. Une candidate annulée ne peut jamais être mise en test ni publiée. La publication transactionnelle modifie l’asset et l’index Famille/Pro après les tests requis ; les profils des autres éditions sont conservés.

Le suivi web est une copie de métadonnées hors des dossiers de montage. Un échec de ce miroir ne fait pas échouer le rapport privé ni le traitement WIM. La libération après annulation et les chronometrages réels restent à confirmer sur Windows/.250 : aucun DISM Windows ni déploiement physique n’a été exécuté depuis l’environnement de développement. La révision ne promet pas de transformer le disque de la VM en SSD ni de garantir une première intégration en quelques minutes.

Fichiers à réunir sur .250

Depuis Activité de déploiement, ouvrir la fiche du poste puis Dossier inventaire. Sur le serveur, les fichiers sont dans D:\AtelierPXE\data\inventaires\NOM-DU-PC\ID-DEPLOIEMENT (adapter le data_dir si différent). Compresser ce dossier permet de réunir :

  • Inventaire-Technique.xml et Inventaire-Technique.csv : matériel, pilotes, état PnP, versions, réglages et sections qui n’ont pas pu être collectées.
  • Diagnostics-Deploiement.zip : result.json, maintenance.json, progress.json, hpia-result.json, journaux des logiciels et mesures de temps.
  • Rapports-HP.zip : analyses, résultats d’installation, CSV et journaux natifs HPIA.

Télécharger aussi le Rapport PDF depuis la fiche du site. Il est généré depuis les données du déploiement et ne se trouve pas nécessairement dans le dossier inventaire. Pour un problème de cache HP, ajouter D:\AtelierPXE\data\hp-repository\worker.log et, si l’installation CMSL a échoué, setup.log. Ces journaux restent sur .250 ; aucune commande PowerShell sur le poste n’est nécessaire pour les réunir. Ne pas transmettre reporting.json, personalization.json, data-runtime.json, une base SQLite complète ni les fichiers de jetons.

Constat sur les rapports HP reçus le 21 octobre 2026

Les rapports portent sur un EliteBook 840 G5 sous Windows 11 Pro 26H2. VLC 3.0.24, Adobe Acrobat 26.002.22031, Chrome 155.0.8059.85, AnyDesk 9.8 et HP Image Assistant 5.3.6 sont déclarés installés et vérifiés. La vérification AnyDesk confirme l’exécutable signe et le service. La préparation n’a pas exécuté Windows Update ni Store, conformément au choix de l’atelier.

Le journal CMSL récent refuse OsVer=26H2 ; son ValidateSet s’arrête a 25H2. Les anciens messages Module HPCMSL introuvable sont anterieurs a ce refus : ne pas conclure qu’une réinstallation de la même bibliothèque corrigera le support d’une nouvelle version Windows.

HPIA reçoit bien Action:Install et IgnoreGenericOsError, puis termine avec code zéro ; pourtant son propre JSON annonce Analyze Action List, EndAnalyze et onze recommandations dont Remédiation est vide. Aucun téléchargement ou résultat d’installation SoftPaq n’est confirmé dans ce passage. IgnoreGenericOsError a exposé le code normal mais n’a pas suffi a obtenir des installations. Une référence HP générique est utilisée pour 26H2 ; la compatibilité certifiée de tous les paquets avec cette version n’est pas établie.

L’inventaire contient 141 périphériques PnP et une erreur code 28, pilote absent, pour PCI VEN_8086 DEV_15D9. HPIA recommande notamment Intel Thunderbolt 3 Secure Connect SP150742 ; son applicabilité et le résultat de son installation doivent être vérifiés. Les périphériques Synaptics Pointing Device / HID ClickPad et les controleurs Intel Serial IO sont déclarés sans erreur à la collecte. Ce constat ne reconstitue pas leur état avant une mise à jour Windows et ne garantit pas le fonctionnement physique du pavé tactile.

Le SSD est déclaré sain, Secure Boot actif, le démarrage rapide désactive et le fuseau W. Europe Standard Time configure. Le système retourne Locale 100c. La section LicencesWindows échoue avec CimException : cet export seul ne permet pas de conclure. L’utilisateur a ensuite confirme que Windows est actif dans Paramètres ; cette vérification humaine est distincte de la collecte CIM en échec. Le pavé tactile reste à tester après redémarrage. L’absence d’OfficeSoftwareProtectionProduct ou de certaines informations batterie peut simplement correspondre à un fournisseur non disponible ; ce n’est pas une preuve de panne.

Correction IQ-5.4.1 et limites

Le client ne retente une installation que si HPIA confirme lui-même un simple Analyze Action List, sans aucun résultat d’installation JSON/XML ou code d’installation CSV. Il crée alors une liste des seuls SoftPaq recommandés avec SSMCompliant=True et utilise la fonction officielle HP SPList une seule fois. Aucun Forcé n’est ajouté. Les résultats absents restent à vérifier, les erreurs réelles restent visibles et l’avertissement de référence générique demeure. Une installation au résultat inconnu n’est pas relancée automatiquement.

Si CMSL refuse OsVer, .250 conserve la vraie version du poste et acquiert seulement les numéros SoftPaq recommandés via Get-HPSoftpaq et Get-HPSoftpaqMetadataFile. Il n’exécute aucun paquet. Les EXE sont contrôlés par signature HP, puis publiés dans un cache identifie par plateforme et version. Le nouveau client recopie les paquets demandes dans le dossier de téléchargement HPIA après contrôle de l’archive et des signatures. L’analyse et les métadonnées restent en ligne : ce cache n’est pas annonce comme un dépôt CMSL intégralement hors ligne. Aucun filtre 25H2 n’est utilisé pour un poste 26H2. Les anciens clients ne reçoivent pas ce nouveau format de cache.

La première machine peut utiliser directement HP si le cache serveur n’est pas encore prêt ; le traitement .250 continue pour les machines suivantes. La présence d’un paquet dans ce cache ne certifie pas sa compatibilité avec une version Windows sans référence HP dédiée. HPIA et ses contrôles restent responsables de l’installation.

Cette correction doit être mise à jour sur .250 et intégrée à un nouveau WinPE pour les prochains déploiements. Une mise à jour du serveur seule ne relance pas HPIA sur un Windows déjà terminé dont le payload a été nettoye. La validation physique finale n’a pas été exécutée depuis l’environnement de développement.

Installation automatique et page HP sur le site - IQ-5.4.3

Le test physique du 21 octobre valide maintenant l’installation silencieuse des onze SoftPaq recommandés sur le HP : neuf retours zéro et deux retours 3010 (Intel Serial IO et HP Hotkey Support), avec redémarrage manuel demande. Le JSON HP confirme Analyze Action Install et les onze remédiations INSTALL_COMPLETED. Ce test ne valide pas a lui seul le cache .250, un flash BIOS ni tout le matériel après redémarrage.

La préparation automatique conserve la commande validée après le premier démarrage Windows, si HPIA est coché. Elle conserve les avertissements de version comme information et les vraies erreurs comme erreurs. Elle ne réactive ni Windows Update ni Microsoft Store. La chaîne de reprise BIOS reste activé.

Après HPIA, le plus récent Readme natif d’installation est copié dans le dossier propre au déploiement, sous le nom Rapport-Installation-HP.html, et dans C:\IQ_\Rapports\Rapport-Installation-HP.html. La page d’analyse avant installation ne peut pas remplacer ce bilan. Les rapports des anciens passages restent conservés. Les tests autonomes conservent leur copie dans leur propre dossier et ne remplacent pas le bilan du déploiement.

Les noms HP comme Readme (20261021 152514).html sont maintenant acceptes dans le ZIP ; l’ancien filtre excluait les parentheses. .250 conserve Rapports-HP.zip et extrait une copie du bilan dans <data_dir>\inventaires\NOM-PC\IDENTIFIANT\Rapport-Installation-HP.html. Les autorisations sont les mêmes que pour les inventaires et le PDF. Le bouton Rapport HP (HTML) télécharge la page dans l’activité de déploiement et dans la fiche ordinateur. Le HTML reçu du poste reste une pièce jointe ; il n’est pas exécuté dans l’origine de la console.

La réponse serveur contient l’empreinte de cette page, vérifiée par le poste avant l’enregistrement de l’accusé de réception. Le nettoyage final vérifie encore la présence et les empreintes du ZIP et du HTML sur .250. Un serveur indisponible ou un rapport non confirmé conserve les fichiers locaux pour une nouvelle transmission. Un HPIA qui ne produit aucun bilan d’installation ne reçoit pas un faux rapport de succès.

Mettre la console à jour puis reconstruire et importer WinPE IQ-5.4.3 sur .250 avant le prochain déploiement. Une mise à jour du serveur seule ne remplace pas les scripts embarques dans un ancien boot.wim. Attendre la fin de la maintenance WIM en cours avant de lancer cette mise à niveau.

Retest HPIA sans redéployer Windows - IQ-5.4.2

Les rapports du 21 octobre montrent que la reprise SPList a bien fonctionne, mais que les deux commandes avec AutoReport se sont terminées comme Analyze Action List, sans résultat de remédiation pour les onze recommandations. Ignorer 4104 ne suffit donc pas. La nouvelle commande retire AutoReport du passage d’installation, sélectionne explicitement InstallType:AutoInstallable et conserve Action:Install et IgnoreGenericOsError. Ce changement doit encore être validé avec le vrai exécutable HP ; les simulations ne prouvent pas le comportement de sa version 5.3.6 sur ce poste.

Une référence générique reste indiquée dans le résultat mais ne transforme plus une installation confirmée en échec. Tous les SoftPaq recommandés doivent avoir un résultat confirme. Des résultats absents, des paquets manuels et des erreurs d’installation restent À vérifier. Les pilotes incompatibles ne sont pas forces et aucun Forcé n’est ajouté.

Sur un HP Windows déjà installé, ouvrir Tester-HPIA.cmd dans le dossier contenant Test-HPIA.ps1, HP-ImageAssistant.ps1 et Unattend.ps1. Accepter la demande administrateur. Le lanceur crée la tâche AtelierPXE-HpiaTest sous SYSTEM, comme la préparation réelle. Aucune commande PowerShell ne doit être saisie sur le PC. Les futurs déploiements fournissent aussi ce lanceur dans C:\IQ_\Constructeur.

Le test utilise le HPIA signé déjà présent dans Program Files et uniquement les serveurs HP par Internet. Il ne réutilise pas les identifiants temporaires ni le résultat terminé d’un ancien déploiement et ne valide donc pas le cache .250. Il ne réinstalle ni Windows ni les autres applications et ne modifie pas le statut historique du déploiement sur le site.

Une mise à jour BIOS peut redémarrer le poste : la tâche de démarrage et le checkpoint privé sont créés avant le lancement, puis HPIA reprend après changement du démarrage Windows. La limite de trois reprises et le refus des installations concurrentes restent actifs. Un redémarrage demande par un pilote ordinaire reste manuel. La tâche est retiree à la fin d’un résultat terminal ; une exécution interrompue n’est pas relancée dans le même démarrage.

Les rapports de chaque test et l’archive ZIP se trouvent dans C:\IQ_\Rapports\HPImageAssistant\Tests\IDENTIFIANT. Le ZIP voisin IDENTIFIANT.zip contient hpia-result.json et les rapports natifs HP des passages successifs. L’état et les paquets temporaires sont conservés dans C:\ProgramData\AtelierPXE-HpiaTest pour diagnostic et reprise ; ils ne contiennent aucun jeton de déploiement. Une nouvelle exécution terminée est conservée séparément et ne remplace pas les preuves précédentes.

Le même envoi indiqué un échec du cache serveur avec un argument Property invalide. Le constructeur d’archive utilise maintenant des objets a propriétés réelles pour Measure-Object et Sort-Object sous Windows PowerShell 5.1. Le journal worker.log inclut aussi l’emplacement et la pile en cas d’autre erreur CMSL. La prochaine synchronisation sur .250 doit confirmer la résolution ; un échec du dépôt reste distinct du traitement HPIA sur le poste.
